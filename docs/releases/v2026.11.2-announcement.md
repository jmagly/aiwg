# AIWG 2026.11.2 - Hand off your session and find the right template

AIWG 2026.11.2 helps you carry work into a new session and gives your assistant the right template for issues, pull requests and reports. It also brings prompt-time discovery to Codex and fixes how Factory/droid receives AIWG instructions.

## Leave the next session a useful starting point

A checkpoint can now include a handoff document and a short prompt for your next session. Record what the work covers, what remains, the constraints to keep and the files to read:

```bash
aiwg checkpoint create --handoff --name next-session \
  --scope "Finish the settings page" \
  --todo "Check keyboard navigation" \
  --constraint "Keep the existing layout" \
  --artifact docs/settings-plan.md
```

AIWG saves those details beside the checkpoint. Anything you leave out stays visibly marked for completion, so review the handoff before passing it on. `aiwg checkpoint recover next-session` prints the saved prompt and document paths without changing your files. Your older checkpoints still work. See the [checkpoint reference](https://github.com/jmagly/aiwg/blob/v2026.11.2/docs/cli-reference.md#aiwg-checkpoint--workflow-resume-positions-and-session-handoffs) for the full flow.

## Give your assistant the right starting format

Bug reports, feature requests and pull requests now have discoverable templates. Discovery results and prompt-time suggestions name related templates, and a component's details show which templates it uses. These links come with the package, so they work without building a local index first.

Ask your assistant to find the issue or PR skill for your task and read its template before writing. AIWG's output policy now requires the relevant template and its required sections. Issue and PR checks warn when required headings are missing, while optional sections stay optional. Progress updates focus on completed and pending acceptance criteria, checks and blockers. See [Find One Capability](https://github.com/jmagly/aiwg/blob/v2026.11.2/docs/getting-started/first-success-find-capability.md) to start with a plain-language request.

## Get more useful discovery suggestions

Long requests now give more weight to your main intent and less to incidental words or code examples. Weak suggestions call for another lookup before the assistant declines. Discovery can build a missing project index on first use; prompt-hook lookups stay read-only. In a read-only workspace, an existing index remains usable with a stale-data warning.

Requests passed through hook instructions also keep backticks and shell substitutions as text, preventing those parts of your request from running as shell commands.

## Use discovery in Codex and Factory/droid

Codex now receives prompt suggestions through its project hooks file. You must trust the project and review the hook in Codex; AIWG explains that next step without granting trust for you.

Factory/droid now gets hooks in the format droid reads. Interactive sessions receive prompt discovery. Non-interactive `droid exec` receives a startup instruction to discover first and read the relevant template, because it does not run prompt hooks. Supported model IDs also replace aliases that droid 1.0 rejected. See the [hook guide](https://github.com/jmagly/aiwg/blob/v2026.11.2/docs/hook-patterns.md) for setup details.

## If you are upgrading

- After updating, ask your assistant to refresh AIWG so managed hooks, scripts and rules receive the fixes.
- In Codex, complete project trust and hook review when prompted.
- Refresh preserves recorded operator edits and keeps hooks installed by `aiwg use all`.
