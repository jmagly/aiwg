# AIWG 2026.11.0 - Choose your Flue app's skills, install them as a package, run on Cloudflare

“Add the SDLC and voice skills to my Flue app as a package, and run it on Cloudflare.” This release completes the package and Cloudflare parts of the Flue integration that started in 2026.10.19. You pick which AIWG bundles your app gets, you can install them from npm instead of copying files, and your app can run on Cloudflare Workers as well as Node.

```bash
aiwg use sdlc --provider flue --package
```

## Pick only the skills your app needs

Choose bundles one at a time, then apply them together:

```bash
aiwg use sdlc --provider flue --declare
aiwg use voice-framework --provider flue --declare
aiwg refresh
```

Your app gets only what you declared. To drop a bundle later, run `aiwg remove voice-framework --provider flue --declare`, then `aiwg refresh`. In the default mode, refresh then removes the dropped bundle's files, but only the ones AIWG put there and you haven't changed. Edited files stay, and AIWG tells you which ones it kept. In copy or package mode, a dropped bundle stays until you run `aiwg remove voice-framework`.

## Install AIWG as a package

Add `--package` and your app imports AIWG skills, specialists and tools from the new `@aiwg/flue` npm package instead of copying them into your source tree. Install the package at the same version as your AIWG CLI:

```bash
npm install @aiwg/flue@2026.11.0
```

Package mode is remembered, so `aiwg update` and `aiwg refresh` keep using it.

## Run your Flue app on Cloudflare

Set `target: 'cloudflare'` in your `flue.config.*` and AIWG generates code that works in a Worker. Your app reaches AIWG through a remote AIWG server. You start that server with `aiwg mcp serve --transport http --project <dir> --token-env <NAME>`; it requires a token and is tied to one project. The [remote setup guide](https://github.com/jmagly/aiwg/blob/v2026.11.0/docs/providers/flue-remote.md) has the full command. The Worker reads the server's address and token from its Cloudflare bindings, so no secret goes into your code. Start with the [Cloudflare example](https://github.com/jmagly/aiwg/blob/v2026.11.0/examples/flue-cloudflare/README.md).

Cloudflare support is tested in Cloudflare's local runtime, and one run on real Cloudflare passed all seven checks. Cloudflare Sandbox and Containers, shared multi-user AIWG servers, and sandboxes or approval hooks are not part of this release. The [Flue guide](https://github.com/jmagly/aiwg/blob/v2026.11.0/docs/providers/flue.md) covers the supported setup and its limits.

## Other fixes

- **Older AIWG configs load again.** Projects whose `.aiwg/aiwg.config` was written by an older AIWG version no longer fail to load.
- **Two addons no longer overwrite each other's agent.** The verbalized-sampling agent is now called `verbalized-content-diversifier`, so it can be installed alongside the writing-quality agent of the old name.
- **Skills that move tiers are cleaned up safely.** When a skill moves between the always-loaded and on-demand tiers, AIWG removes the old copy only if you haven't edited it.
- **A security update for the VS Code extension's sign-in library.**

## If you are upgrading

- If you use verbalized-sampling and **not** writing-quality, delete the old `.claude/agents/content-diversifier.md` (or the matching file for your AI tool) after updating.
- For Flue apps set up with 2026.10.19, run `aiwg refresh` to regenerate the AIWG files. `aiwg-utils` is no longer added to Flue apps by default; add it back with `aiwg use aiwg-utils --provider flue` if you use it (add `--package` too if your app uses package mode).
