# AIWG 2026.11.10 - Plan pipelines and roll out features

> Help me maintain my CI pipeline and decide how to roll out this feature.

AIWG 2026.11.10 adds an optional framework for CI/CD pipelines and expands feature-flag planning, with a new LaunchDarkly addon. It also updates tool setup and gives you more control over everyday requests.

## Design and maintain your pipelines

> Design a CI pipeline for this project using GitHub Actions.

AIWG already offered nine frameworks for work from software delivery to research and media. Now `cicd-complete` adds one more opt-in framework for designing and maintaining the pipelines that build, test and deliver your code.

Run `aiwg use cicd-complete`, then ask “design a CI pipeline.” It can assess your existing setup, help diagnose failing or flaky jobs, and prepare pipeline files for Gitea Actions or GitHub Actions. Start with the [CI/CD quickstart](../frameworks/cicd-complete/quickstart.md).

## Plan flags when they help

> Should this be behind a flag? Plan the rollout, tests and eventual removal.

The SDLC framework already included feature-toggle checklist items and a toggle card. Now it offers optional, vendor-neutral planning when a flag would help. A flag lets you control who gets a feature separately from deploying the code. Decline a suggestion and it stays declined for that work.

Ask “plan feature flags” to record the owner, default behavior, rollout, rollback, tests and removal task in the expanded card. See the [flag-planning guide](../frameworks/sdlc-complete/feature-flags.md).

For LaunchDarkly, run `aiwg use launchdarkly` and ask “set up LaunchDarkly.” The new opt-in addon guides you through setup to a first flag in your app, then helps with targeting, gradual rollouts and stale-flag cleanup. It also supplies CI/CD flag checks for flag state, tests, code references, rollout and cleanup when LaunchDarkly is your selected flag provider. The [LaunchDarkly guide](../addons/launchdarkly/user-guide.md) has examples.

## Refresh Devin and Antigravity

> Refresh AIWG for Devin and Antigravity using their native setup.

AIWG already supported both tools. Devin now uses its own `.devin/` paths and migrates older `.windsurf/` installs; the Windsurf alias still works. Antigravity now gets native MCP plugin files and a prompt hook that looks up relevant AIWG guidance. Existing flat MCP configuration is preserved with a warning.

## Ask for an answer without tools

> Answer from what you already know, without running any tools.

AIWG already asked assistants to look up guidance before working. Now an explicit “no tools” request suspends that lookup and tool-based reads for your turn, so you can ask for an answer from the context already loaded.

## Carry issue details into planning

> Plan a new issue from our bug template, with two labels and a milestone.

AIWG already helped plan, create and edit issues. Now issue commands accept repeated labels and a milestone, verify edits, and let you choose a template when planning or creating an issue.

## Give PR Steward your project rules

> Give Claude Code's PR Steward our repository's delivery instructions.

AIWG already recorded delivery policy. Now setting `delivery.pr_steward_guidance: true` lets a Claude refresh supply that policy to PR Steward. It covers signing, checks and protected paths, while preserving guidance you wrote yourself.

## Choose a worker strategy

> Favor lower-cost workers for routine work and keep my automatic tier ceiling.

AIWG already selected workers by role and project policy. Now `defaults.workerSelection.strategy` offers `cost-effective`, `balanced` or `quality`. You can also set an automatic tier ceiling; a project can narrow your ceiling but cannot silently raise it. Leave both unset to keep existing selection behavior.

After updating, ask your assistant to refresh AIWG for your tools. See the [full CHANGELOG](https://github.com/jmagly/aiwg/blob/v2026.11.10/CHANGELOG.md#20261110---2026-11-28) for every change.
