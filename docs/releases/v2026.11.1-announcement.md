# AIWG 2026.11.1 - Find the right skill and save your place

“Help me find the right skill for this request.” AIWG 2026.11.1 brings skill suggestions into new requests in Claude Code and Muse, adds checkpoints for long work, and makes worker runs more dependable.

## Find a skill when you ask

When a new request arrives in Claude Code or Muse, AIWG runs a read-only discovery lookup and adds the top three matching skills, with instructions for loading them, to the model's context. You can describe your goal without first choosing a skill from the catalog. The hook skips short acknowledgements, option picks and slash commands, and gives up silently after 1.5 seconds.

Prefer to turn those suggestions off? Set `AIWG_PROMPT_DISCOVERY=0`. This hook does not cover Codex or Hermes yet.

The discovery rule now calls for `aiwg discover` at the start of every new request, with continuations of an already-discovered request exempt. Discovery itself is faster and quieter, with better ranking: a shared trigger word no longer counts as a full match, and the stale relationship-table notice no longer appears on every lookup. See [Find One Capability](https://github.com/jmagly/aiwg/blob/v2026.11.1/docs/getting-started/first-success-find-capability.md) for the lookup flow.

## Save your place in long work

Use a checkpoint to record where to pick up next:

```bash
aiwg checkpoint create --name next-step --note "Continue the draft"
aiwg checkpoint list
aiwg checkpoint recover next-step
```

You can also record a phase, step and related artifacts. Checkpoints keep the working directory and Git HEAD when available; the list shows newest entries first. Recovery reports where to resume without changing your repository. The [checkpoint reference](https://github.com/jmagly/aiwg/blob/v2026.11.1/docs/cli-reference.md#aiwg-checkpoint--workflow-resume-positions) explains the commands.

## More dependable worker runs

Workers that exit quickly under load are now confirmed as stopped more reliably. Each attempt's captured output is sealed read-only, and a retry cannot reuse its capture or output path. Relaunching a task without retry flags is refused while an earlier attempt remains unconfirmed. Other projects' workers no longer take this workspace's worker or review slots, though shared host limits still apply. Launch errors now name invalid path flags, and a final-output folder that does not exist yet no longer causes a false disk-space failure. See the [worker guide](https://github.com/jmagly/aiwg/blob/v2026.11.1/docs/getting-started/worker-dispatch.md) for running workers.

## Choose how to deliver changes

`aiwg run skill aiwg-pr` opens and merges pull requests, with delivery settings for signed local merges, unsigned local merges or tracker merges. Signed local merges are optional. If signing is configured but no merge route is set, the merge stops and asks the Steward to choose one. Use the [Steward guide](https://github.com/jmagly/aiwg/blob/v2026.11.1/docs/getting-started/first-success-ask-steward.md) to ask for setup help.
