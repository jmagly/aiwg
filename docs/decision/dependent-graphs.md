# Dependent decision graphs (offline contract)

`DecisionGraph.v1.schema.json` and `planDecisionGraph` define an opt-in, **non-executable** graph contract. No credential lookup, transport, Flow node kind, speculative dispatch, action authorization, or runtime execution is added. Existing independent rulesets are unchanged. The caller supplies a trusted set of resolved artifact digests; the graph's model-visible state cannot resolve pins or change edges.

A graph has one entry, explicit terminal sinks, ascending integer stages, named projected outputs/inputs, and pinned definition and binding digests. Every non-entry input must be supplied exactly once by a predecessor in an earlier stage. All nodes must be reachable from the entry. Schema and semantic validation reject duplicate IDs, missing pins, illegal projection sources, ambiguous inputs, cycles, unreachable roots, undeclared terminals, and excessive depth/fan-out **before** any execution could occur. The canonical plan sorts nodes, terminal IDs, and edges; insertion order has no effect on its digest.

Same-subject nodes in a stage are *planning candidates* for native batching only if their target, model, egress, declared state digest, and incoming evidence projection are identical. Different subjects remain separate candidates for bounded fan-out. An edge always crosses a stage, so dependent nodes never enter their predecessor's batch. This grouping alone does not prove runtime compatibility: the future executor must recheck projected state, resolved pins, transport capability, policy, and actual envelopes before scheduling. A plan is not a dispatch authorization.

The declared attempts, deadline, tokens, cost in micro-units, fan-out, beam width, depth, and concurrency are upper bounds, not grants. This version validates numeric ceilings and structural depth/fan-out/beam constraints; it does **not** yet enforce cumulative usage, per-stage accounting, unknown-cost handling, cancellation, discarded speculation, stable shortlist ties, or the minimum of caller/workspace/provider limits. `pattern` records intended use (`shortlist-rerank`, `taxonomy-beam`, `extractor-verifier-fallback`, or `custom`) but provides no executable templates. Shortlists and beam search can multiply calls and amplify early errors. Downstream action authorization must remain separate even after a validated terminal outcome. Flow-hosted execution must retain existing run/node/activation/invocation identities and use the existing `decision-evaluate` bridge; there is no second workflow engine here.

This contract is experimental and excluded from runtime/release qualification until offline pattern fixtures, Flow integration, budget/lineage and adversarial tests, and paired FlowGraph benchmarks pass. Never treat a graph plan or model evidence as permission to execute actions.
