# Dependent decision graphs (offline contract)

`DecisionGraph.v1.schema.json` and `planDecisionGraph` define an opt-in, **non-executable** graph contract. No credential lookup, transport, Flow node kind, speculative dispatch, action authorization, or runtime execution is added. Existing independent rulesets are unchanged. The caller supplies a trusted set of resolved artifact digests; the graph's model-visible state cannot resolve pins or change edges.

A graph has one entry, explicit terminals (sinks, or nodes whose outgoing edges are all guarded), ascending integer stages, named projected outputs/inputs, and pinned definition and binding digests. Every non-entry input must be supplied exactly once by a predecessor in an earlier stage. All nodes must be reachable from the entry. Schema and semantic validation reject duplicate IDs, missing pins, illegal projection sources, ambiguous inputs, cycles, unreachable roots, undeclared terminals, and excessive depth/fan-out **before** any execution could occur. The canonical plan sorts nodes, terminal IDs, and edges; insertion order has no effect on its digest.

Same-subject nodes in a stage are *planning candidates* for native batching only if their target, model, egress, declared state digest, and incoming evidence projection are identical. Different subjects remain separate candidates for bounded fan-out. An edge always crosses a stage, so dependent nodes never enter their predecessor's batch. This grouping alone does not prove runtime compatibility: the future executor must recheck projected state, resolved pins, transport capability, policy, and actual envelopes before scheduling. A plan is not a dispatch authorization.

The declared attempts, deadline, tokens, cost in micro-units, fan-out, beam width, depth, and concurrency are upper bounds, not grants. The optional `stageBudgets` declares full limits for specific stages. Numeric bounds and stage topology are validated before dispatch. `GraphBudgetLedger` provides synchronous pre-dispatch reservations using trusted full-attempt/token/monetary estimates (including an unknown-cost bound), fake-clock deadlines, cancellation and per-stage/cumulative concurrency. `admittedDecisionFlowAdapter` attaches it at Flow's existing `invokeNode` seam; the host must supply honest conservative bounds and actual attempt/usage counts. An overrun cancels the graph but cannot undo a billed remote call. Backend adapter retries consume the reserved attempt budget; Flow retries stay disabled. `pattern` records intended use (`shortlist-rerank`, `taxonomy-beam`, `extractor-verifier-fallback`, or `custom`) but provides no executable templates. Shortlists and beam search can multiply calls and amplify early errors. Downstream action authorization must remain separate even after a validated terminal outcome. Flow-hosted execution must retain existing run/node/activation/invocation identities and use the existing `decision-evaluate` bridge; there is no second workflow engine here.

`auditGraphEvidence` is an offline, post-hoc evidence auditor for a validated plan. It revalidates plan topology, projects only named predecessor outputs into dependent inputs, records source result digests, accounts for used and unused observations, rejects undeclared outputs and unbounded unknown cost, and returns a canonical digest. Caller/workspace/provider ceilings narrow the graph ceiling; observed overages produce `budget-exhausted` (cancellation dominates). This **does not** reserve budgets before dispatch, measure overlapping wall time, enforce per-stage limits, or implement execution. A forged plan, missing observation, or unknown cost without a bound fails closed. Receipts are data, not permission to act.

`decisionGraphToFlow` compiles validated DAG nodes into the **existing** Flow `skill` node, using a caller-authorized stable `decision-evaluate` skill ID; it never introduces a new node kind or performs a transport call. It rejects identities Flow cannot represent rather than silently renaming them. Flow provides its run/node/activation/invocation IDs, approval and permission boundary, zero graph-level retry and resource accounting; the host adapter remains responsible for binding selection, priced unknown-cost policy, durable receipts and action authorization. Declared boolean `when` guards on edges compile to Flow state/route predicates, so false branches do not invoke their nodes. Predicates are fixed by the trusted artifact, not model-authored control flow. `decisionRulesetFlowInvoker` binds authenticated host-resolved artifacts to the existing `evaluateDecisionRuleset` dispatcher, passing only declared predecessor evidence and the Flow run/invocation identities; it derives attempt/token/cost usage from dispatcher results. A host projector chooses declared outputs and cannot add graph-control fields. The existing decision receipt store can be supplied by the host and the Flow checkpoint belongs to Flow. `finalizeDecisionGraphRun` cross-checks Flow result outputs and resource totals against the host's per-invocation observations, records stable terminal selection plus stage/batch/attempt/Flow identity lineage, and returns no value on non-complete outcomes. Flow v1alpha1 calls a guarded-off branch `NO_RUNNABLE_NODES` rather than `skipped`; the finalizer treats it as unused **only** when all missing nodes have explicitly inactive route trace (or descend from those nodes), and keeps the original Flow failure status in its receipt. `FileGraphRunReceiptStore` writes private create-once receipts; its unkeyed digest detects accidental changes, not malicious replacement. The host must persist the Flow checkpoint/dispatcher receipts separately. `decisionGraphParallelDispatch` uses Flow's existing parallel-dispatch seam. Native batching is opt-in behind an authenticated transport capability; candidates must share declared subject/target/model/state/egress/pins **and identical actual Flow inputs**. The ledger reserves every group member atomically before a provider call; provider responses are correlated by stable question ID even if returned out of order. Different subjects fan out separately; unknown/duplicate IDs fail closed without individual retry after uncertain remote execution. Native batch receipts mark actual executions separately from mere planner candidates. Provider adapters must report per-question resource shares honestly. Native batching within a single decision ruleset remains owned by the existing decision dispatcher; no second batching transport is introduced. In particular a Flow run report is not yet a complete graph receipt or qualification for speculative execution.

`shortlistRerankTemplate`, `taxonomyBeamTemplate` and `extractorVerifierFallbackTemplate` provide pinned, caller-authored stage layouts. The fallback template guards its ordinary-LLM branch on a declared boolean verifier output; its verifier is also terminal when the branch is not taken. The Flow finalizer selects the deepest reached terminal with a stable ID tie-break and never treats model text as an instruction. With `details` configured, the taxonomy template adds fixed stage-three detail nodes guarded by the selector's declared boolean outputs. `graphBeamFlowInvoker` is a deterministic, host-side selector at Flow's skill invocation seam: it accepts only finite numeric scores for the fixed candidates, applies the minimum authorized beam width, and uses candidate ID as the stable tie key. It has zero inference usage; it cannot invent a detail node. The host must wrap it with the same admission ledger, and should not route the selector through model inference. `selectDecisionBeam` deterministically sorts finite scores with an explicit binary ID secondary key and bounded width. Paired fake-transport tests compare shortlist/rerank, taxonomy-beam and extractor/verifier/fallback against independently authored explicit Flow baselines. They assert fixed-task output parity and provider-reported calls, tokens, cost and logical duration. No external Jev/LLM or collector was contacted: fixed answers prove routing/resource-accounting parity, **not** real-model accuracy, billable price or wall-clock latency. Real inference, complete graph receipts, beam selection during execution and G5/G6 evidence are still missing. This contract remains experimental and excluded from release qualification. Never treat a graph plan or model evidence as permission to execute actions.
