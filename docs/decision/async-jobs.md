# Asynchronous decision jobs: contract only

The versioned `DecisionJob.v1` schema and `validateDecisionJob`/`assertJobTransition` are **offline validation only**. Durable storage, submission, dispatch, polling, cancellation, retries, export, deletion, and provider integration are **not enabled**. AIWG would own a future job lifecycle over bounded synchronous calls: Jev has no documented asynchronous job endpoint. A job is not a provider-native bulk batch, and completion never authorizes a downstream action.

Each item has a stable caller ID and fingerprint, a digest-only subject reference, pinned definition/binding digests, independent state, and append-only attempt history. A job carries explicit tenant/project/workspace/principal scope, an immutable fingerprint, retention times, budgets, and exact counts for every item state. Job status never substitutes for checking the item-level outcomes. `execution-unknown` cannot be reported as a clean cancellation or completed result. The contract rejects invalid state transitions, changed identity/pins/attempt history, duplicate IDs, unsupported fields, and a success without a receipt reference. It does **not** provide object authorization by itself.

Future runtime work must implement atomic durable compare-and-swap transitions, credential-safe input storage, non-guessable scoped handles, principal authorization for every operation, admission and fair per-principal quotas, bounded pagination, cancellation/remote ambiguity reconciliation, replay-safe crash recovery, per-item usage accounting, D10 retention/legal hold, D14 telemetry, and offline negative fixtures. Different item subjects must never be merged into one native shared-state request; native same-subject batching is only within an eligible item. No release/runtime qualification may claim these protections from this contract alone.
