# Asynchronous decision jobs: offline experimental lifecycle

The AIWG-owned `DecisionJob.v1` contract validates item identities, scope, immutable pins, budgets, retention deadline, guarded transitions, and exact item-state summary counts. Jev has **no documented asynchronous job endpoint**. A job is not a provider-native bulk batch; completion does **not** authorize any downstream action.

`FileJobStore` persists immutable, mode-0600 revisions using exclusive hard-link publication and directory sync; `MemoryJobStore` supports offline fixtures. Both provide scoped acquisition and compare-and-swap. `DecisionJobRuntime` provides offline submit, read-only ordered pagination/poll, cancellation, eligible-failure requeue without dispatch, expiry reconciliation, tombstoning and scoped legal-hold toggles that reject deletion while held. `OfflineJobWorker` fences an individual fixture attempt durably before invoking an explicitly supplied test executor; a thrown, aborted or invalid fixture result becomes execution-unknown. Its callback is **not** an admitted backend provider integration. Restart reconciliation never replays a fenced attempt; finalization retries only a bounded compare-and-swap after concurrent sibling completion, never the executor. Different item subjects are presented separately. The caller must derive the full scope from trusted authentication, **not** model input; the runtime compares the authenticated scope before submit or transition. Other scopes receive no job record. A duplicate job ID with unchanged identity returns the existing snapshot; changed pinned identity is rejected. Tombstones prevent ID reuse. An expired running item with a dispatched attempt becomes `execution-unknown`, never cleanly canceled. Retry of unknown items is forbidden by the contract. Out-of-order completions preserve original item order. All offline operations are disabled from provider-facing CLI/API surfaces.

An explicit host-only `admittedJobItemExecutor` bridge composes the existing synchronous evaluator with a durable D03 receipt store and enabled scheduler policy. It rejects unbound principal/workspace, missing cost limits, changed ruleset/definition/binding/input digests and incomplete receipts before exposing an item reference. Same-subject native batches remain within one item invocation. This bridge is not exposed through CLI/API. The worker requires an explicit durable token/cost reservation for admitted evaluator callbacks, sums reservations across all sibling item attempts under the job CAS, and refuses dispatch that exceeds the pinned job budget; the bridge also rejects plans whose host estimates exceed that fence. Reservations are conservative and not refunds. `OfflineJobScheduler` bounds one offline queue and round-robins authenticated principal/project lanes, with deterministic result slots and no retry amplification; it does not coordinate separate processes. For same-host local-filesystem deployments, `FileJobQuotaStore` wraps **every** journal writer in an ownership-checked directory lock and atomically checks per-project and per-principal queued/running/retained item, serialized byte, pinned token/cost, attempt-call and job ceilings before acquisition/transition. Its fail-closed lock is not automatically reclaimed after a process crash; an operator must establish the owner is gone before removing a stale lock. `FileJobPollLimiter` adds a bounded, private local-filesystem polling ledger under the same lock; a host can attach it to `DecisionJobGateway` before handle parsing so even forged-handle enumeration consumes quota. It enforces per-project and per-principal windows across same-host instances. Neither component is a distributed-filesystem coordinator or a replacement for provider admission. Bypassing the wrapper with direct `FileJobStore` writes bypasses aggregate quotas. `accountDecisionJob` reads the scoped D03 and D04 receipts to report known token/cost totals, unknown usage, labeled estimates and budget exceedance; it ignores per-answer allocations in native batches and rejects cross-item shared-state ownership. This report is read-only and **not** a transactional pre-dispatch quota reservation; a host must not enable jobs just because these pieces exist.

`createOfflineDecisionJobService` wires a local transactional quota journal, bounded polling ledger, scheduler, worker, runtime, metadata-only telemetry and object gateway into one disabled-by-default host assembly. It requires an independent D10 deletion authority and export authorizer; its host must supply authenticated actors and admitted item executors. `DecisionJobGateway` is a host-only object-authorization adapter. It encrypts randomized opaque handles with an injected 256-bit host key and binds them to the authenticated tenant/project/workspace/principal plus job fingerprint, creation time and expiry. It rejects cross-scope, forged, expired and deleted handles without looking up another scope. Optional host-supplied list/export capabilities bind encrypted pagination cursors to the authenticated scope, reject stale pages and require explicit export authorization. It is **not** a CLI/API route; the host must obtain actor and key from trusted authentication/secret storage, not model-visible state, and must not emit handles to telemetry.

**Do not expose this runtime to users yet.** There is no job-level provider scheduler, distributed quota/fairness authority, cursor limits, retry policy integration, retained-result payload byte accounting, protected payload store, D10 deployment-backed erasure/backup/key-destruction evidence (local hold, purge and independent tombstone fixtures do not prove an external backup is purged), deployed D14 OpenTelemetry collector qualification (golden partial/retry/cancel/expire/restart/finalization fixtures now exist), or full crash/load qualification. The journal retains digest-only historical metadata after tombstoning until the host invokes `FileJobStore.purgeDeleted` through D10's independently persisted lifecycle tombstone/eraser flow. Purge removes revision files and leaves a local no-reuse marker; an independent `externallyDeleted` lifecycle authority is required to block backup resurrection if a restored directory loses its marker. Raw inputs/results are never stored in revisions. Do not store PII or secrets in IDs, scope fields, errors, or fingerprints. Retention expiry changes lifecycle state but does not automatically invoke the eraser. File stores require a local filesystem supporting atomic hard links; they do not provide a distributed CAS. No claim of exactly-once provider billing or execution is made.

Different item subjects must never be merged into a shared-state request; eligible same-subject question batching belongs inside a single item and its existing admission and receipt flow. Before enabling jobs, bind the host gateway to a real authentication and secret-key service, require the quota wrapper for every writer, wire the durable polling limiter at the host boundary and add cursor limits, and qualify isolation, recovery, saturation and accounting under deployed infrastructure. Until then this remains an offline foundation, not a production asynchronous jobs feature.
