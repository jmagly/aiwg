# Semantic decision-result cache

The result cache reuses evidence from an earlier, side-effect-free decision. It is separate from exact invocation-receipt replay, compiled-schema caches, and provider prompt-prefix caches. It ships disabled: callers must supply an enabled, versioned cache policy, declare the evaluation side-effect-free, and choose an explicit TTL.

## Identity and freshness

`decision-semantic-key/v2` hashes canonical JSON for the definition, ruleset, binding, adapter, prompt, acceptance, calibration, runtime policy, backend/model compatibility, primitive, projected input, subject identity, projection and egress policies, and capability mode. Strings and object keys are NFC-normalized before sorting; colliding keys after normalization are rejected. Numbers use JSON canonical number representation. The evaluator rejects a non-NFC projected input before dispatch when cache mode is enabled; otherwise the normalized key could equate two byte-distinct adapter inputs. Entries keyed with v1 are not migrated into v2: they miss until filled under the new contract. Changing any field produces a miss. The digest is scoped again by tenant, project, and workspace in storage.

Pinned models may be reused only for the exact requested/actual version. A moving alias requires a registry-generated compatibility snapshot, an explicit approved-version set, and an unexpired validity window. Expired or unknown snapshots bypass reuse; the cache never guesses the version an alias currently serves.

Hits preserve the original result, evaluation time, actual model, uncertainty, calibration status, source invocation, and receipt. The new caller receipt says `cache-hit` and `providerAttempted: false`; it must not be rendered as fresh inference. TTL expiry and policy-version changes prevent reuse, but TTL alone never establishes identity.

## Integrity and access

Every read revalidates schema version, immutable identity, result digest, entry digest, safe terminal state, scope, policy, and freshness. The filesystem store uses mode-restricted files and atomic no-overwrite publication. Host-authenticated actors must hold per-operation `read`, `write`, `invalidate`, `export`, or `delete` permission, and the actor scope must match the entry. Storage paths hash scope plus key to avoid cross-project substitution. Deletion writes a body-free, mode-0600 audit tombstone (including whether a legal hold applied), then unlinks the live content file. A backup restored over a deleted key remains inaccessible, and the tombstone prevents refill. Unlink is not secure erasure of underlying media or backups. The local legal-hold flag preserves only permitted audit facts, **not** the original cached content. `purgeExpired(actor, now)` sweeps expired live entries in the authenticated workspace; retention jobs must schedule it explicitly. Deployments remain responsible for encryption, backup erasure/retention and full legal-hold compliance on the containing volume; do not enable for sensitive data without these controls.

Only successful evidence is cached by default. A policy may opt into short negative caching solely for deterministic `invalid-input`; authentication, authorization, boundary denial, transient failures, and execution uncertainty are never reusable. A rejected or crashed fill publishes nothing. In-process single-flight collapses concurrent fills for one scoped key. The filesystem store also serializes read/check/fill/publication across local processes using a mode-0600 lock per scoped key. A dead same-host owner can be recovered; unknown/remote owner locks fail closed rather than triggering duplicate provider execution. Distributed volumes require a reviewed lease/fencing mechanism before enabling writes.

## Experimental evaluator integration

`evaluateDecisionRuleset` accepts an optional `resultCache` host policy. The caller must supply authenticated scope, explicit side-effect-free freshness policy, durable original receipt store, policy/calibration pins, `identityFor` (complete trusted host pins), and an awaited `recordCallerReceipt` persistence callback. Enabled reuse is restricted to one evaluation, one target, zero retries, no batching or context/scheduler mode; unsupported configurations reject before dispatch. The evaluator validates the definition/ruleset/binding/adapter/primitive/model, acceptance/calibration/runtime-policy pins and actual projected input against the supplied identity before lookup. The host must attest prompt, subject, backend, projection/egress and capability-mode pins: the evaluator cannot derive those from the portable artifact alone. The adapter cannot supply these values. An alias additionally requires `verifyAliasSnapshot` to re-check the registry snapshot on **every** lookup; a failed check bypasses reuse. Exact invocation receipt replay takes priority over this cache.

The response's `spec.cache` is the newly issued caller receipt. A hit retains the historical result and its historical attempts (not new provider usage) and labels the caller receipt `cache-hit`, `providerAttempted: false`; the original completed receipt is revalidated before returning it. Callers MUST persist the caller receipt separately and display historical attempts as source evidence, never as current adapter work. A failure of the persistence callback aborts release of the result.

Telemetry reports only `hit`, `miss`, `bypass`, `stale`, `invalidation`, and `single-flight` with an opaque operation ID. Semantic keys, input-derived digests, subject identities, and entry IDs are not telemetry fields. Hit-side savings are labeled **estimates from the original request**, not measured counterfactual provider savings; missing input/output tokens or cost remain `null`, never fabricated as zero. Original provider usage remains attached to original evidence and is never counted again as new usage.
